# Broker ownership and performance release gates (draft)

**Scope:** AttoRedis, AttoKafka, AttoRMQ/AMQP, and AttoNATS. This document specifies independent verification requirements, not release certification.

1. Compile **real `.atto` broker sources** with Java/GraalVM, LLVM AOT, and .NET NativeAOT from pinned toolchain heads. Never substitute a Rust, Java or C# implementation for the production broker logic. Fail closed if any required compiler cannot lower a source feature.
2. Each actor has a separate trusted heap/arena domain and an isolated logical stack. Guest references are **32-bit offsets**, with trusted out-of-band actor/arena/generation/allocation identity. Check every access and forbid stale references. 32-bit guest offsets do not imply 32-bit host pointers.
3. Mailboxes are the default transport; send consumes a unique owned value only after linearizable admission. Failure must return ownership or fail-stop before a duplicate owner exists. Shared memory is optional and capability-gated: immutable published values or generation-fenced reader/writer guards. No naked pointers or live exclusive borrows cross suspension, actor hops or teardown.
4. Actor state is sealed: `critical-read` permits concurrent readers; `critical-write` permits one writer; actor generations and STOP fence outstanding accesses. `define supervisor` / `define pub supervisor` remain source-level constructs, not host orchestration substitutes. Multithreaded execution is the default, with `serial actor` explicitly serial.
5. **Only nonblocking I/O.** Every networking/storage operation must use asynchronous transport with bounded queues and backpressure. No blocking calls on carrier/scheduler workers; test on real sockets and disk fault conditions. Channels and `io.in`/`io.out` pipes must retain ownership and EOF/error/cancellation semantics.
6. Keep all new guest source in `.atto`; legacy `.ores` is allowed only for explicit compatibility/migration tests. Rust may implement the shared borrow checker, adversarial oracles, and benchmarks, but cannot replace Atto broker features.
7. For each broker, declare one reference implementation (Rust baseline by default; a pinned Java Kafka baseline is permissible) and one workload/feature profile. Warm-up, payload sizes, connection counts, persistence/durability policy, TLS/auth settings, hardware, CPU affinity, memory ceilings and concurrency must match. Report a distribution of **completed correct operations per second**, tail latency, error rate and memory pressure.
8. **Release target:** `Atto_median_throughput / reference_median_throughput >= 0.70` separately for each agreed protocol workload, with correctness, durability and safety gates already green. No score is assigned without executed comparable measurements. Do not hide slower workloads in an aggregate. Treat a regression in safety or protocol correctness as FAIL even if throughput is high.

The five Rust tests in `tests/broker_ownership_cross_model_v1.rs` exercise **abstract ownership/arena/guard models only**. They do not certify native physical heap placement, I/O, concurrent memory safety, source-to-MIR lowering or broker parity. Backend-local in-pass borrow checking must match the canonical Rust checker on the same typed CFG; disagreements block code generation. Do not launch Rust per source statement in optimized compiler paths.
